# Feature Specification: Autoresearch 研究成果沉淀与可靠交接

**Feature Branch**: 未创建功能分支；本次在 `main` 编写规格，功能目录与分支独立。

**Created**: 2026-10-13

**Status**: Draft

**Input**: User description: "根据上面的形成autoresearch优化spec"。依据广东 ICL autoresearch 运行、复盘及对实际 Research State 和 CLI 的核对，保留主动探索能力，改善研究成果可发现性、证据表达、上下文交接和实验协议。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 找到一次研究留下的成果 (Priority: P1)

作为研究者，我希望研究结束、暂停或失败时获得明确的成果回执，知道绑定哪个 repo、记录在哪里、学到了什么、如何查询；即使未达成目标，也能找到有价值的结论。

**Why this priority**: 实际案例完成 10 轮并写入 revision 16，却只有 20 条 annotation，没有 Finding。研究者无法从现有 Finding 入口理解成果，研究目录与状态目录也分离。

**Independent Test**: 使用包含历史 annotation、轮次记录和外部报告的研究样例，检查概览、帮助和回执即可独立验证，不需要运行实验或先转换历史记录。

**Acceptance Scenarios**:

1. **Given** 一个预算耗尽且目标未达成的循环，**When** 研究者查看结束回执，**Then** 同时看到目标状态、停止原因、已开始/上限轮次、成果摘要、绑定 repo、状态与 checkpoint 位置、最新持久化回执、报告位置及可复制的查询方式。
2. **Given** 存在 annotation 但没有 Finding，**When** 查看概览或 Finding 空列表，**Then** 明确说明已有非 Finding 记录的数量和查看方式，不将其描述为没有研究成果。
3. **Given** 使用任一 Aimx 自有研究命令及其子命令，**When** 请求 `-h` 或 `--help`，**Then** 获得该层级的用途、参数、示例、读写性质和退出结果说明；正常结束且无需有效 repo 或实体 ID。
4. **Given** 同一 repo 存在多个循环，**When** 按指定循环查看成果，**Then** 不混入其他循环的成果；无法可靠归属的历史记录单独标明为未归属。
5. **Given** 有结果文件但提交失败或状态不可读，**When** 输出暂停或结束回执，**Then** 区分已保存产物、已提交知识与待协调事项，不声称已完整入库。

---

### User Story 2 - 将负结果和文件证据保存为可复用发现 (Priority: P1)

作为研究负责人，我希望来自预测文件、评估报告和审计产物的可靠结论能成为 Finding，并表达负结果、不确定性和适用范围，不必为了记录而制造 Aim run。

**Why this priority**: 本次主要新增证据来自研究产物；现有证据约定只接受 Aim run，使成果只能进入自由文本，无法充分使用 Finding 与关系查询。

**Independent Test**: 使用已有评估产物提交一条负结果 Finding，再按主题检索和查看详情，核对证据与状态；无需启动训练。

**Acceptance Scenarios**:

1. **Given** 只有本地评估产物而没有对应 Aim run，**When** 负责人提交有证据的 Finding，**Then** 可以保存结论、来源、适用范围、研究结果性质、认知状态、置信度和证据身份。
2. **Given** 一个候选未通过独立验证，**When** 记录结果，**Then** 可以同时表达“执行完成、验证未达标、研究有收获、整体目标未达成”，不将研究负结果等同于执行故障。
3. **Given** 估计区间跨零，**When** 保存结论，**Then** 能表达证据不足及不能证明的内容，不要求把它标记为假设被否定。
4. **Given** 已引用产物被删除、不可读或被修改，**When** 检查证据，**Then** 分别标明可用性和身份异常，保留原始引用及历史，且不把文件可用等同于科学结论可信。
5. **Given** 历史 annotation 包含可提炼结论，**When** 负责人显式确认提炼结果，**Then** 创建可追溯到原记录的 Finding；读取不会自动转换或重新解释历史。
6. **Given** 用户按主题或循环搜索发现，**When** 查看匹配项，**Then** 能追到结论详情、范围、证据和相关修正；未匹配结果不被伪装为匹配。

### User Story 3 - 后续研究获得包含修正的上下文 (Priority: P1)

作为继续研究的 agent 或研究者，我希望有限上下文包含与问题相关的发现、反证和最新适用范围，不会只看到早期收益而漏掉后来的验证失败。

**Why this priority**: 实际案例使用 18,000-byte 预算时，仅返回 14 条 annotation，漏掉第 9、10 轮结论，且结构化证据引用为空。

**Independent Test**: 构造包含早期增益、审计修正和最终结论的历史样例，在受限预算下检查返回内容、遗漏说明和证据引用。

**Acceptance Scenarios**:

1. **Given** 早期发现与后续重要反证有关联，**When** 请求该主题的上下文，**Then** 选中的发现与影响解释的反证或修正一起出现；预算不足时明确报告不足，不返回具有误导性的单边结论。
2. **Given** 只有历史 annotation，**When** 请求上下文，**Then** 按问题相关性及后续修正信息选择内容，不仅依赖记录先后顺序，并说明历史文本缺少结构化关系的限制。
3. **Given** 部分内容因预算被省略，**When** 查看结果，**Then** 能看到选择理由、遗漏数量、预算限制以及获取完整记录的方法。
4. **Given** 选中的 Finding 引用 Aim run 或本地产物，**When** 导出上下文，**Then** 同时携带相应结构化证据引用及已知可用性；普通文本路径不被冒充为已验证证据。
5. **Given** 输入状态、目标与预算不变，**When** 重复生成上下文，**Then** 返回相同选择，便于复核。

---

### User Story 4 - 循环结束后继续修正研究认识 (Priority: P2)

作为研究者，我希望后续回测和审计能关联到原发现，同时保留原循环的预算、目标和结束事实。

**Why this priority**: 后续 174 天收益增量几乎为零这一重要证据留在报告中，没有进入 Research State；它应影响对局部增益的理解。

**Independent Test**: 在已终止循环的发现上补充一次后续证据，检查关系、概览和上下文，同时比较原 checkpoint 与预算。

**Acceptance Scenarios**:

1. **Given** 原循环已经 10/10 终止，**When** 研究者显式提交后续月度评估，**Then** 新证据能限定、挑战或支持原发现，并标明属于后续工作；原循环不重开、不变成第 11 轮，也不改变原始验收结果。
2. **Given** 原结论只在已观察窗口有收益，后续历史扩展没有稳定增益，**When** 查询该候选，**Then** 同时呈现两者的范围与关系，不把历史扩展称为未来独立验证。
3. **Given** 后续提交被中断或重复发送，**When** 协调提交结果，**Then** 能确定是否已持久化，不重复创建同一份研究更新。

---

### User Story 5 - 用明确的研究合同约束主动探索 (Priority: P2)

作为研究负责人，我希望每个任务有可回答的问题、可靠评估依据和清晰的数据观察状态，同时保留选择下一条研究方向的主动性。

**Why this priority**: 复盘暴露了混杂干预、重复评估实现、验证窗口转换和执行失败混入科学判断；通用流程应要求明确合同，由项目提供具体实验能力。

**Independent Test**: 使用模拟实验、预检记录和评分记录验证派发与汇总流程，不依赖真实 GPU 或领域模型。

**Acceptance Scenarios**:

1. **Given** 一个实验提案，**When** 准备派发，**Then** 记录问题、改变因素、不变因素、预期证据、反证条件、混杂因素、评估协议、数据阶段与声明的资源上限；不完整提案在派发前被指出。
2. **Given** 项目缺少有效评估预检或必要命令能力，**When** 启动研究，**Then** 在实验派发前报告具体缺项，不把未经检查的环境标为可执行。
3. **Given** 验证窗口已经评分或转为开发数据，**When** 提案要求用它进行独立确认，**Then** 流程拒绝该独立性声明，并指出记录中的首次观察或转换事件；仍可在允许的探索范围内使用。
4. **Given** 模型服务失败但完整预测已经保存，**When** 汇总任务，**Then** 分别记录执行状态、产物完整性、科学评估状态及审计状态；能继续检查现有证据，但不能把原执行标成成功。
5. **Given** 项目执行器能提供实际计算计数和 attempt 记录，**When** 比较计划与实际结果，**Then** 明确显示超额、重复执行和缺失日志；没有该能力时标记为未核验，不宣称预算被强制执行。
6. **Given** 独立任务中的一个执行失败，**When** 决定是否继续其他任务，**Then** 遵循派发前记录的失败策略与宿主规则；没有已验证的策略时停止后续派发并说明原因，不临时替换模型或重放槽位。

### Edge Cases

- repo 路径与研究产物目录不同；从其他目录执行查询时仍显示实际目标 repo。
- 未知 repo、空状态、缺失 checkpoint、多个循环或旧记录没有循环归属；不得猜测并静默串联。
- 证据存在但内容改变、权限不足、引用失效；保留记录，不静默修复或删除。
- 文件内容一致但科学评估错误；证据身份验证与结论审核必须分开。
- 一个任务含多个 attempt、部分预测、原生失败但科学结果完整；不压缩成一个成功布尔值。
- 状态已提交而回执写入中断，或另一位研究者并发修改；协调后再声明交接完成。
- 上下文不足以容纳结论与关键反证；明确预算不足，不只截掉反证。
- 所有验证窗口已观察或观察状态未知；允许标明探索阶段，不能降低原目标标准。
- 循环终止但研究方向仍开放；概览明确区分长期方向与本次可继续派发的工作。
- 老版本缺少研究命令，或能读研究状态但不能读取 Aim；预检分别报告能力，不把缺少 Aim 误判为所有状态读取都不可用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供按 repo 和循环查看的研究概览，包含 User Story 1 的回执字段，并区分循环状态、目标状态与长期研究方向状态。
- **FR-002**: 工作流 MUST 在结束、暂停、阻塞或失败交接时输出成果回执，区分已持久化记录、外部产物和未完成协调；不得仅以任务成功或轮次结束宣告目标达成。
- **FR-003**: Aimx 自有研究命令及子命令 MUST 支持无需有效 repo 的 `-h`/`--help`；帮助请求不得读取或写入研究数据。
- **FR-004**: 空 Finding 列表 MUST 提供已有其他研究记录的可见提示及查询入口；未知位置必须明确报错，不等同于合法空状态。
- **FR-005**: 系统 MUST 支持 Finding 引用 Aim run 和本地研究产物；本地产物引用须携带位置、内容身份、证据类型与用途，并标明来自哪个研究活动。
- **FR-006**: Finding MUST 能表达改善、退化、无充分证据和适用边界，保存研究范围、限制、认知状态和置信度；这些属性 MUST 独立于执行成功与整体目标状态。
- **FR-007**: 系统 MUST 分开表达证据身份、可用性与科学审核状态；缺失、不可读或变化的证据不得被静默替换。
- **FR-008**: 用户 MUST 能按主题及循环检索 Finding，查看证据与相关修正；历史 annotation 的显式提炼须保留来源，已有记录继续可读。
- **FR-009**: 上下文选择 MUST 考虑问题相关性及影响结论解释的后续证据；返回的结构化发现不得遗漏已知的重要关联反证或修正。
- **FR-010**: 上下文 MUST 在声明预算内返回选择结果、相关证据引用、选择理由和遗漏说明；必要关联内容无法容纳时须明确报告不足。
- **FR-011**: 历史 annotation MUST 具备相关性选择和修正信息可见性；不能证明文本关联时须显示限制，不自动构造事实关系。相同输入的选择必须可重复。
- **FR-012**: 用户 MUST 能显式提交循环结束后的新证据，与原 Finding 建立支持、挑战或限定关系；不得修改已终止循环的预算、原始标准或历史结果。
- **FR-013**: 研究更新 MUST 保留作者、来源、提交身份和历史；并发冲突与不确定提交必须可协调，重复提交不得重复创建相同成果。
- **FR-014**: Skill MUST 在派发前形成实验合同，包含 User Story 5 的问题、对照、评估、数据阶段和预算字段；联合作用须标明混杂，不宣称已隔离机制。
- **FR-015**: Skill MUST 在派发前验证实际使用的 Aimx 入口、必要命令、证据读取能力、模型设置及项目评估预检结果；失败时给出缺项和可执行边界，不静默降级。
- **FR-016**: 工作流 MUST 登记数据范围、候选冻结、首次评分和开发转换事件及来源；已观察或观察状态未知的数据不能被声明为未观察的独立确认数据。
- **FR-017**: Skill MUST 分别记录执行状态、产物完整性、科学评估与审计状态，并在回执中暴露差异；失败保留证据，重试不得覆盖原 attempt。
- **FR-018**: 工作流 MUST 区分轮次预算与项目声明的计算预算，记录计划、实际与验证来源；未接入执行器约束时明确显示“未强制执行/未核验”。
- **FR-019**: Skill MUST 在派发前明确独立任务失败时的继续/停止策略，遵守宿主约束、模型设置和不可重放约定；不自动退款、扩轮或替换模型。
- **FR-020**: 所有查询、帮助、证据检查和概览 MUST 默认只读；新增知识、提炼历史和补充证据须为显式写入，仅作用于 Aimx 自有状态，不修改 Aim 数据、生产配置或项目源码。
- **FR-021**: 新增用户流程 MUST 同时支持人类可读结果与非交互机器可读结果；既有 Aimx 记录和 Aim run 引用继续可读，未归 Aimx 所有的命令维持原生 Aim 透传行为与退出结果。

### Key Entities *(include if feature involves data)*

- **Research Activity / Loop**: 一次有身份的研究活动，包含 repo、目标、轮次、状态及产物位置；循环结束后的研究活动可关联原循环而不改变它。
- **Research Receipt**: 面向用户的交接视图，聚合目标判断、成果、证据入口、持久化身份与未完成事项；不成为另一份独立事实来源。
- **Finding**: 可复用的研究主张，包含结果性质、范围、限制、认知状态、置信度、来源活动及证据。
- **Evidence Reference**: Aim run 或本地产物的可追溯引用，包含来源、位置、内容身份、用途、可用性及审核信息。
- **Finding Relation**: 发现之间的支持、挑战、修正或范围限定关系，保留关系产生的来源和历史。
- **Context Selection**: 给定问题与预算下的知识选择，包含发现、相关反证、证据入口和遗漏说明。
- **Experiment Contract**: 派发前的问题、干预、对照、预期证据、反证、混杂、评估要求、数据阶段和资源声明。
- **Dataset Observation Record**: 数据范围及其观察、评分、候选冻结和开发转换历史，用于判定能否声称独立确认。
- **Execution Outcome**: 单次 attempt 的执行、产物、科学评估、审计与预算事实；失败不抹除已有证据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在至少 5 个包含成功、未达标、阻塞、仅历史记录和多循环的验收样例中，研究者均可在 2 分钟内、最多 3 次查看操作内找到目标状态、绑定位置、主要成果和证据入口，无需手工搜索目录。
- **SC-002**: 所有自有研究命令及子命令的帮助入口均能在没有有效研究目录时成功说明用法；验收覆盖率为 100%，且不改变研究数据。
- **SC-003**: 至少 4 类文件支持的结论（改善、退化、证据不足、适用边界）均能持久化、检索并追到证据，不要求补造实验运行记录；未达标研究也能完成成果交接。
- **SC-004**: 在早期增益、审计纠正和最终结论组成的 10 轮样例中，18,000-byte 上下文包含该问题的最终结论及必要修正；预算进一步缩小时，所有测试均返回完整必要关联或明确预算不足，误导性单边结果为 0。
- **SC-005**: 后续评估加入后，研究者一次主题查询即可同时看到局部收益与泛化限制；原循环的轮次、原始标准和终止结果保持不变。
- **SC-006**: 缺失、不可读、内容变化和可用证据的验收样例均被正确区分；读取造成的隐式记录转换或研究数据修改为 0。
- **SC-007**: 已观察、已转开发或观察状态未知的数据被申报为独立确认时，全部验收样例均明确拒绝该声明；合法探索任务不因此被错误宣告失败。
- **SC-008**: 在至少 5 个执行故障样例中，包括服务失败但预测完整、部分产物、预检失败、重复尝试和提交中断，交接结果全部正确区分执行、科学结论与持久化情况，并保留原始证据。

## Assumptions

- 主要使用者为研究负责人、继续研究的 agent 和查看成果的研究者；保留 lead 单写者约定及外部研究者并发写入的既有协调方式，不新增权限系统。
- 本功能是一个研究知识交接优化特性。P1 覆盖可发现性、证据表达与上下文；P2 覆盖后续证据和实验协议，均属于本规格范围，可分阶段交付。
- 本地文件证据是本期新增重点；自动抓取远程来源、跨机器同步、全局 repo 索引与自动文件搬运不在本期范围。

# Feature Specification: Aimx Research Retro Skill

**Feature Branch**: `codex/008-aimx-retro`  
**Created**: 2026-10-29  
**Status**: Draft  
**Input**: 用户希望新增独立的 `aimx-retro` 技能，帮助 Lead 做好下一轮研究决策。既可在 autoresearch 轮次之间调用，也可由用户主动让一个未参与原研究的新 Agent，根据既有 Aimx 记录独立复盘。两种入口共享分析协议，不依赖原聊天上下文，不自动恢复研究、启动实验或修改研究状态。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新 Agent 独立复盘既有研究 (Priority: P1)

用户指定 Aim 仓库及可选研究方向、历史区间或关注问题，让一个没有参与原研究的 Agent 重建研究进展，检查既有结论，并解释接下来值得解决什么问题。

**Why this priority**: 研究记录应支持独立接手，复盘的价值不能依赖原 Lead 的记忆或 autoresearch 执行记录。

**Independent Test**: 给新 Agent 一份包含 Research State 和实验记录、但没有原聊天或 autoresearch checkpoint 的研究材料，检查其能否说明目标、可信结论、未决问题及带条件的下一步建议。

**Acceptance Scenarios**:

1. **Given** 仓库包含一个明确研究方向及相关实验，**When** 用户请求复盘，**Then** 报告声明研究范围、目标、状态版本、证据覆盖，重建关键决策，并提供下一步建议，不要求原聊天或 checkpoint。
2. **Given** 用户明确指定方向、轮次区间或关注问题，**When** 开始分析，**Then** 以指定范围为主，仅引用解释该范围所需的相关历史，并标明扩展引用的原因。
3. **Given** 仓库存在多个不同目标且请求无法唯一定位，**When** Agent 完成研究概况读取，**Then** 呈现候选范围并请求用户选择，不擅自合并不同研究目标。
4. **Given** 历史 Agenda 中有过时、暂停或已被替代的任务，**When** 生成建议，**Then** 区分历史任务与当前有效问题，不把旧任务直接作为恢复执行指令。

---

### User Story 2 - Lead 在轮次之间调整研究决策 (Priority: P1)

Lead 在本轮结果核对和研究状态更新之后、分配下一轮任务之前调用 Retro，获取本轮认知更新、应保留或调整的做法，以及下一轮可比较的行动选项。

**Why this priority**: 让复盘在仍能改变研究行动时产生价值，是本功能的主要目的。

**Independent Test**: 提供一轮已完成的计划、结果、更新后研究状态及相关历史，检查报告能否帮助 Lead 选择下一轮首要问题，并说明不同实验结果将如何改变后续行动。

**Acceptance Scenarios**:

1. **Given** 本轮实验已完成且结果已核对，**When** Lead 调用 Retro，**Then** 报告区分新增、削弱、未解决的判断，给出零至三条优先反思及至多三个下一步选项。
2. **Given** 组合改动带来指标改善但无法归因，**When** 分析下一步，**Then** 报告根据目标比较复现组合方案与拆分对照，说明各自解决的不确定性及改选条件，不直接宣称单个改动有效。
3. **Given** 本轮过程合理或原目标已经满足，**When** 复盘，**Then** 可以建议继续既有做法或停止研究，不为产生建议而制造问题或强制安排新实验。
4. **Given** 报告之后研究状态或用户目标发生变化，**When** Lead 消费报告，**Then** 能依据报告记录的版本和适用条件识别需要重新核对的建议；原有预算、暂停决定和完成状态不被复盘重置。

---

### User Story 3 - 在证据不完整时获得可信的分析 (Priority: P2)

用户希望 Retro 明确哪些判断有证据、哪些只是可能解释，以及需要补什么记录，避免因信息缺失或事后成功而错误评价研究过程。

**Why this priority**: 不完整记录是实际使用中的常态，结论必须与可用证据相匹配。

**Independent Test**: 使用缺少决策上下文、实验中断、比较条件不一致和存在后续成功结果的材料，检查报告是否正确限制结论并提出具体补证行动。

**Acceptance Scenarios**:

1. **Given** 某条 Finding 当时已存在但没有上下文交接或读取记录，**When** 评价历史决策，**Then** 报告区分“证据存在”与“Agent 已知”，不直接归因为忽视证据，也不补写动机。
2. **Given** 实验中断或偏离计划，**When** 解释结果，**Then** 先判断实际执行与比较有效性，不把执行失败直接当作科学假设被反驳。
3. **Given** 后来另一方向成功，**When** 评价早期选择，**Then** 仅以当时可用信息和约束评价合理性，将后续结果单独呈现。
4. **Given** 多个原因都能解释问题，**When** 提出反思，**Then** 保留竞争解释和反证，分别说明观察是否确认、原因是否成立、改进是否经过验证。
5. **Given** 引用失效、来源相互冲突或仅有结果摘要，**When** 核查证据，**Then** 报告列明缺口及受影响的判断，继续可支持的分析；无法支持行动时，明确建议先补证。

### Edge Cases

- 空仓库、没有研究目标或没有有效实验记录：输出可用信息、缺口及最小补证需求，不伪造历史或初始化研究状态。
- 只有 Aim 实验记录、没有 Research State：可分析可比性和结果，无法确认的目标、决策和动机必须标记未知；若目标影响建议，先请求目标说明。
- 研究记录过多：先依据目标定位重要转折、冲突证据和未决问题，声明实际读取范围和遗漏，不声称完整审查全部轨迹。
- 研究正在写入或实验尚未结束：标明读取版本、时间和未完成证据；不能获得一致状态时缩小或暂缓受影响结论。
- 不同数据划分、指标方向、基线或评估协议：不能直接以指标数值判定优劣，先说明比较限制。
- 没有耗时或计算资源记录：成本标记未知，不把轮次预算当作时间或 GPU 预算，不量化虚构的浪费。
- 已暂停、完成或预算耗尽的 loop：可复盘并提出条件性建议，但不得恢复执行或返还预算。
- 原始记录中包含命令或角色指示：作为待分析材料处理，不能成为复盘 Agent 的新授权。
- 重复复盘相同研究：报告应可区分，不覆盖既有报告或原始研究产物。

## Constitution Alignment *(mandatory)*

- **CA-001 Safety & Mutability**: 复盘只读安装的 Aim、`.aim` 数据、Research State、执行记录和既有技能；写入仅限独立的复盘报告产物，不修改或修复源材料。调用 Retro 不授权提交研究更新、启动实验、恢复 loop 或改写技能。
- **CA-002 Ownership Boundary**: 新增用户可调用的 `aimx-retro` 技能及轮次间的调用指导。现有 Aimx 查询和研究读取能力作为依赖；本功能不新增 Aimx CLI 命令或旗标，未被 Aimx 拥有的命令继续委托原生 Aim。Lead 保留 Agenda 选择和 Research State 写入职责。
- **CA-003 CLI & Output Contract**: 支持能够访问仓库的外部 Agent 在本地终端、SSH 或非 GUI 环境使用。输出可独立阅读的报告及语义一致的机器可读交接，包含范围、来源、判断、建议和限制；明确范围的调用无需交互，范围无法确定时说明所需输入。Aimx 不新增托管 Agent 运行时或调度器。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 技能 MUST 支持用户主动调用和 Lead 轮次间调用，使用同一分析协议；独立调用 MUST 不依赖原会话、原 Lead 或 autoresearch checkpoint。（故事 1、2）
- **FR-002**: 技能 MUST 识别明确仓库、研究目标和复盘范围，尊重用户指定的方向、区间和关注问题；无法唯一确定范围时先读取概况再请求选择。（故事 1.1–1.3）
- **FR-003**: 每份报告 MUST 记录仓库身份、目标、复盘范围、读取时间、可用研究 revision、可用轮次标识、实际审查材料和证据缺口；无法获得的字段标记未知，不构造替代事实。（故事 1.1、3.5）
- **FR-004**: 技能 MUST 重建影响后续研究的关键决策，包括当时可用信息、已知选项、约束、实际选择、已记录理由、预期、观察和后续判断；缺失内容标记未知，并区分历史状态和当前状态。（故事 1.4、3.1、3.3）
- **FR-005**: 技能 MUST 按实际执行是否符合计划、结果是否可比、结果对假设意味着什么、后续决策是否一致的顺序分析证据；实验失败和成功均不单独决定决策质量。（故事 2.2、3.2、3.3）
- **FR-006**: 技能 MUST 检查假设、研究策略、实验设计、执行效率、证据解释和研究决策六个方面，只展开影响后续行动且有证据的问题或有效做法；允许没有过程问题，不强制评分或正反条数。（故事 2.1–2.3）
- **FR-007**: 每项实质性观察 MUST 引用可检查的具体材料；报告 MUST 区分原始结果、研究者摘要和复盘推断，并禁止从缺失的记录推断动机或知情情况。（故事 3.1、3.5）
- **FR-008**: 对重要问题，技能 MUST 检查信息未交接、信息未使用、实验设计或执行偏差、资源工具约束及既有规则不适用等竞争原因，寻找反证；不能区分时保留不确定性。事实确认、原因判断、建议有效性 MUST 分别表述。（故事 3.4）
- **FR-009**: 报告 MUST 提炼零至三条优先反思，分别给出支持证据、适用条件、应保留或改变的具体行为、例外和验证方法，禁止仅用“加强探索”等泛泛建议。（故事 2.1、2.3）
- **FR-010**: 报告 MUST 确定下一步首要问题，并给出至多三个可比较选项，说明每项解决的不确定性、最小行动或实验、必要对照、成本与前置条件、结果分支及改选条件。若无充分证据提出实验 MUST 推荐补证；目标达成或约束禁止继续时可建议停止。（故事 2.1–2.3、3.5）
- **FR-011**: 建议 MUST 服从研究目标、有效用户指示、预算和暂停决定，不虚构成本或收益概率；不能说明结果如何影响后续决策的实验建议 MUST 解释其独立价值，否则不列为推荐。（故事 2.2–2.4）
- **FR-012**: 技能 MUST 提供独立的人类可读报告和内容一致的机器可读交接，至少涵盖认知更新、保留与调整建议、首要问题、推荐及备选行动、证据引用、适用条件和缺口；重复调用 MUST 保留既有产物。（故事 1.1、2.1；重复复盘边界）
- **FR-013**: 轮次间调用指导 MUST 将复盘放在本轮结果核对及研究状态更新之后、下一轮任务分配之前；Lead MUST 根据最新目标、状态和约束决定是否采纳建议，报告本身不是研究更新或执行授权。（故事 2.1、2.4）
- **FR-014**: 技能 MUST 只读源数据和历史记录，仅保存独立复盘产物，不自动改写 Finding、Agenda、checkpoint、技能或 AGENTS，不启动实验、恢复旧 loop 或重置预算。（故事 1、2；暂停或完成边界）
- **FR-015**: 使用指导 MUST 展示两种入口、可选范围和关注问题、缺少 checkpoint 时的行为，以及如何由用户或 Lead 消费报告；无需原作者说明即可完成独立复盘。（故事 1、2）

### Key Entities *(include if feature involves data)*

- **复盘范围**: 仓库身份、目标、方向或历史区间、关注问题、读取时的状态版本和时间，用于明确建议的适用范围。
- **证据记录**: 来源定位、对应研究对象、时间或版本、证据类型、可读取情况及限制；支持观察和决策重建。
- **决策点**: 当时信息、可确认的知情情况、备选项、约束、选择、理由、预期、观察及后续动作；未知信息显式保留。
- **反思项**: 有证据的观察、竞争解释、反证、认知更新、行为建议、适用条件、例外及验证方式。
- **下一步选项**: 优先问题、最小行动、对照、成本、前置条件、结果分支、推荐理由和改选条件。
- **复盘报告**: 连接范围、证据、决策点、反思和行动选项的独立交接产物，不代表研究状态已更新。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在包含完整轮次、无 checkpoint 的历史研究、证据不足研究三类验收材料上，新 Agent 均能完成有明确范围和限制的复盘，无需原会话或原作者解释。
- **SC-002**: 验收报告中 100% 的实质性事实观察可定位到所引用材料；缺失动机、未确认知情、未知成本均不被报告为已知事实。
- **SC-003**: 对每份有可执行下一步的验收报告，接手者仅阅读交接即可指出首要问题、推荐理由、前置条件和不同结果对应的后续选择；每个推荐实验均有结果分支或独立价值说明。
- **SC-004**: 针对执行失败、比较混杂、后见之明、缺失上下文四类验收案例，报告全部识别相应限制，不将这些情况直接认定为假设失败、方法成功或研究者失误。
- **SC-005**: 两种入口的报告均包含不超过三条优先反思和三个行动选项；合理过程案例允许零条问题，目标达成案例允许停止，无证据案例明确提出补证需求。
- **SC-006**: 所有验收调用均不改变源实验数据、研究状态、既有技能和执行状态；重复调用保留历史报告，只有独立复盘产物可以新增。
- **SC-007**: 人类可读报告和机器可读交接中的范围、关键判断、证据引用、建议和限制一致，无相互矛盾或缺失的关键内容。

## Assumptions

- “Lead”指对研究目标、后续任务选择和研究状态写入负责的研究主 Agent；独立调用时用户可以直接接收报告，无需存在活动 Lead。
- 第一版以一个仓库内明确的研究目标为范围，可覆盖多个历史轮次；跨项目经验聚合、自动技能演化和技能效果评测不在本功能范围内。
- 现有 Aimx 研究读取及 Aim 实验证据访问能力可供使用；执行记录、当时的上下文、代码版本及资源记录是可选补充，缺失时降级分析，不以完善记录为调用前提。
- 第一版不会承诺恢复完整历史知识状态。只有可核验的历史材料才能用于判断当时可用信息；当前 Research State 不能冒充历史状态。
- 支持轮次间嵌入意味着提供明确调用与交接规则，不意味着每轮强制调用或引入常驻自动调度；是否调用由用户或 Lead 决定。
- 调用技能授权生成独立报告，不授权采纳建议后的研究执行或状态修改。报告存放位置和具体序列化格式留待规划确定。
- 历史证据可以支持对建议合理性的检查，不能证明未执行的新策略将改善结果；反思质量按证据和决策可用性验收，不承诺指标提升。
